Reverse-engineering notes for base/submit.cmd (classic CP/M-86 1.1 SUBMIT)
==========================================================================

Provenance
----------
base/submit.cmd is the classic Digital Research SUBMIT, NOT the CCP/M-86 3.1
source in this directory. Embedded string reads " copyright(c) 1977, digital
research ". The CCP/M-86 submit.a86 is a different program: it spawns each
line via BDOS fn 150 (CLI command) with console attach/detach and process
priority, and contains no $$$.SUB writer at all (zero '$$$' references).
The two share only a name.

CMD layout (from cmdinfo)
-------------------------
  file offset 0x0000  len  128   CMD header
  file offset 0x0080  len 1040   CODE group (0x410), BASE(RELOC)
  file offset 0x0490  len 2768   DATA group (0xAD0), BASE(RELOC)
  file total 3968 = 31 x 128-byte records (last record padded)

Extract with:
  dd if=base/submit.cmd of=code.bin bs=1 skip=128  count=1040
  dd if=base/submit.cmd of=data.bin bs=1 skip=1168 count=2768
  ndisasm -b 16 -o 0 code.bin > code.asm

Entry / top level
-----------------
  0x0000  entry: save SS:SP to cs:0x5B / cs:0x59, switch SS to DS, SP=0x130
  0x0017  call 0x70                       ; main
  0x001A  fn 25 (get current disk)  -> [0x100]
  0x0025  fn 32 (get user, DL=FF)
  0x002A  shl ax,4 / or al,[0x100]        ; user<<4 | drive
  0x0037  restore SS:SP
  0x0043  ES = saved SS ; [es:0x805] = 0FFh
  0x004E  fn 0 (system reset) -> exit

  0x0070  main: call 0x147   ; phase 1 - open input .SUB
          main: call 0x214   ; phase 2 - read + $n substitution
          main: call 0x37E   ; phase 3 - write $$$.SUB
          (note: ndisasm mis-syncs one byte at 0x6F; real entry is 0x70
           with push bp / mov bp,sp)

BDOS helpers
------------
  0x005D  bare  int 0E0h / ret            ; CL and DX preset by caller
  0x0060  PL/M-style 2-arg wrapper: DX=[bp+4], CX=[bp+6], int 0E0h, ret 4
  0x00A1  close       (fn 16)
  0x00B4  delete      (fn 19)
  0x00E4  make        (fn 22)
  0x01FD  write record(fn 21)  ; reports "Disk Write Error" at 0x20B
  0x011C  print error string (address pushed as arg)
  0x0126  print "Error On Line " prefix

Phase 3 (0x37E) - the $$$.SUB writer   [DECODED]
------------------------------------------------
  delete($$$fcb)                        ; 0x381 -> 0xB4
  $$$fcb[0x20] = 0                      ; 0x159, current record
  make($$$fcb)                          ; 0x38D -> 0xE4
  if dcnt == 0FFh -> error "Directory Full"
loop:
  count = getbyte()                     ; 0x3A2
  if count == 0 -> close
  DMA[0]       = count                  ; 0x3AF
  DMA[count+1] = 0                      ; 0x3B6
  DMA[count+2] = '$'                    ; 0x3BB
  while count != 0:                     ; 0x3C0 cmp byte [0x9e2],0 / jz 0x3DA
      DMA[count] = getbyte()            ; 0x3C7 / 0x3D0
      count--                           ; 0x3D4
  write_record($$$fcb)                  ; 0x3DA -> 0x1FD
  goto loop                             ; 0x3DD
close:
  close($$$fcb)                         ; 0x3DF -> 0xA1
  if dcnt == 0FFh -> error "Cannot Close, Read/Only?"

  0x3F6  getbyte:  ax = [0x132]; ax--;  [0x132] = ax
                   return [0x1DD + ax]  ; PRE-decrement: walks BACKWARDS

Record format contract with the CCP
-----------------------------------
  byte 0        line length
  byte 1..len   command text, forward order
  byte len+1    00
  byte len+2    '$'

  Lines are emitted in REVERSE order (the line buffer is walked backwards),
  because the CCP reads the LAST record of $$$.SUB first and truncates the
  file as it consumes records. Characters come out in forward order because
  the backwards read is paired with a backwards store into the DMA buffer.

  Implication for the buffer built by phase 2: each line is laid down as
  [text...][length], with the length byte LAST, so that the backwards walk
  encounters the length first.

Phase 1 (0x147) - open the input .SUB   [DECODED]
--------------------------------------------------
  move(src=0x81, dst=0x15B, len=0x7F)   ; copy command tail to param area
  [0x15B + [0x80]] = 0                  ; NUL-terminate using tail length
  move(src="SUB", dst=0x65, len=3)      ; 0x65 = FCB(0x5C)+9 = type field
  open(0x5C)                            ; 0x8E, fn 15
  if dcnt == 0FFh -> "No 'SUB' File Present"
  [0x1DB] = 0x80                        ; force a record read on first getchar

  0x18D getchar:
    if [0x1DB] > 0x7F:                  ; DMA buffer exhausted
        read(0x5C)                      ; 0xC4, fn 20
        if result != 0: return 1Ah      ; EOF -> ^Z
        [0x1DB] = 0
    al = DMA[0x80 + [0x1DB]++]          ; post-increment
    [0x1DC] = al
    if al == CR: bump ASCII line counter [0x136],[0x135],[0x134] ('9'->'0' carry)
    if 'a' <= al <= 'z': al &= 5Fh      ; upcase
    return al

Phase 2 (0x214) - read + substitute     [DECODED]
--------------------------------------------------
  [0x1DD] = 0 ; [0x132] = 0 ; more_lines = 1
  while more_lines:
      linecount = 0
      ch = getchar()
      while ch != 1Ah and ch != CR:
          if ch == LF: ch = getchar(); continue      ; LF skipped
          if ch == '$':
              ch = getchar()
              if ch == '$': emit '$'                 ; $$ -> literal $
              else:
                  n = ch - '0'
                  if n > 9 -> "Parameter Error"
                  [0x9DF] = 0
                  skip to the n'th whitespace-delimited word in [0x15B]
                  emit every char of that word
          elif ch == '^':
              ch = getchar() - 'A'
              if ch > 19h -> "Invalid Control Character"
              emit ch+1                              ; ^A..^Z -> 01h..1Ah
          else:
              emit ch
          ch = getchar()
      more_lines = (ch == CR)                        ; ^Z ends the file
      emit linecount                                 ; LENGTH BYTE LAST

  0x2F7  param word-char fetch: returns 0 at space or NUL, else advances [0x9DF]
  0x32E  skip spaces in the param area
  0x346  putbuf(ch):
           [0x132]++                                  ; PRE-increment
           if [0x132] > 0x7FF -> "Command Buffer Overflow"
           buffer[0x1DD + [0x132]] = ch
           [0x9DD]++
           if [0x9DD] > 0x7D  -> "Command Too Long"   ; 125 = 128-1-1-1

Limits
------
  line buffer   0x1DD .. 0x9DC   2048 bytes, max index 0x7FF
  max line      125 characters   (128 minus length byte, NUL and '$')
  parameters    $0 .. $9, whitespace delimited, taken from the command tail
  escapes       $$ -> '$'        ^A..^Z -> control codes 01h..1Ah
  input is upcased; LF is discarded; ^Z terminates

  putbuf pre-increments and getbyte pre-decrements, so buffer index 0 is never
  written. It stays the 0 written at phase-2 entry, and is what phase 3 tests
  to detect end of data.
